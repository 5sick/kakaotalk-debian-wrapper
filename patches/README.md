# Wine patches

These patches are applied on top of the upstream Wine source by
`scripts/build-wine.sh`. They are derived from Wine and licensed under the
**GNU LGPL 2.1 or later** (see `COPYING.LIB`), like Wine itself.

| Patch | Problem | Fix |
|---|---|---|
| `0001-winex11-ignore-stale-mouse-move-resize.patch` | Qt posts a second `SC_DRAGMOVE` after the mouse button is released. Wine forwarded it to the window manager as `_NET_WM_MOVERESIZE`, so the window kept following the pointer until the next click. | In `move_resize_window`, re-check the real X pointer state and ignore mouse-driven move/resize requests when no button is pressed. Keyboard moves are unaffected. |
| `0002-winex11-composite-gl-alpha-for-dwm-blur-behind.patch` | Qt (and other toolkits) make translucent GL windows by calling `DwmEnableBlurBehindWindow` and rendering alpha. Wine returned `E_NOTIMPL` and only used 24-bit visuals for GL windows, so translucent areas (notification shadows, rounded tooltips) were drawn black. | `dwmapi` records blur-behind on the window. For such top-level windows `winex11` picks an EGL config with a 32-bit ARGB visual for the GL surface and switches the X window to ARGB, and keeps it when `SetLayeredWindowAttributes` would reset the visual. Other windows are unaffected. |
| `0003-winex11-set-min-size-hint-for-resizable-windows.patch` | Wine never told the window manager the minimum size of resizable windows, so WM-driven resizing could shrink an app window to a thin line. | Query `WM_GETMINMAXINFO` (before taking the win data lock) when a resizable window is shown or resized, and set it as the `PMinSize` hint. |
| `0004-shell32-explorer-host-file-manager.patch` | KakaoTalk's "폴더 열기" (open containing folder) starts `explorer.exe /select,<file>` / `SHOpenFolderAndSelectItems` directly, bypassing the folder associations, so Wine's explorer window appeared. | If `HKCU\Software\Wine\Explorer` `"HostFileManager"` names a Unix command, `SHOpenFolderAndSelectItems` runs `<command> --select <unix path>...`, `explorer.exe /select,<path>` runs `<command> --select <unix path>` and `explorer.exe <folder>` runs `<command> --folder <unix path>` (via `__wine_unix_spawnvp`). `explorer.exe /desktop` is untouched; without the value, or if the command can't be started, Wine's explorer is used as before. The launcher points it at `/usr/lib/kakaotalk-debian-wrapper/open`, which calls `org.freedesktop.FileManager1.ShowItems`/`ShowFolders` and falls back to `xdg-open`. |
| `0005-comdlg32-xdg-desktop-portal-file-chooser.patch` | File attach/save dialogs were Wine's Windows-style dialogs. | If `HKCU\Software\Wine\FileDialog` `"HostFileChooser"="Y"`, `IFileDialog::Show` (open/save, no custom controls) and `GetOpenFileNameW`/`GetSaveFileNameW` (no hook/template) call `org.freedesktop.portal.FileChooser` `OpenFile`/`SaveFile` through a new comdlg32 unixlib (`portal.c`, libdbus loaded with `dlopen`, Request/Response signal handled). Filters, initial folder/name, multi-select, folder picking and the `x11:<XID>` parent are passed on. The call runs on a worker thread while the caller's messages are pumped and the owner is disabled. Unix paths below the target of a known folder that is a symlink in the prefix (Downloads, Documents, ...) are returned through that folder; other folders that no drive maps (no `Z:`) are linked into `C:\Linux\` (one kept symlink per picked folder) and returned through it, for open, save and folder picking; if linking fails, files to open are copied to `%TEMP%\host-files\`. Only without a session bus/portal is Wine's dialog shown. The A (ANSI) functions are unchanged. |
| `0006-shell32-browse-for-folder-host-chooser.patch` | Apps that pick folders with the old `SHBrowseForFolderW` still got Wine's folder tree dialog. | With `HostFileChooser` enabled, pick the folder through `IFileOpenDialog` (`FOS_PICKFOLDERS`), so the host file chooser is used. Computer/printer/file browsing keeps the classic dialog. |
| `0007-ntdll-winex11-host-file-links-for-drag-and-drop.patch` | Without `Z:`, files dragged or pasted from Linux became `\\?\unix\...` paths that applications can't open, even files in the shared folders (they are reached through symlinks inside the prefix, and ntdll only maps Unix paths to drives, never back through symlinks). | `unix_to_nt_file_name` and `\??\unix\` names in `get_nt_and_unix_names`: when no drive maps a Unix path, find a symlink in `drive_c/users/<user>/` or `drive_c/Linux/` whose target contains it and use the path through that link (unchanged when a drive maps it); `wine_get_dos_file_name` retries with a larger buffer since the DOS name can be longer than the Unix one. New `ntdll_get_host_dos_file_name()` for files the user hands to an app: if still unreachable, only that file or folder is linked into `C:\windows\temp\host-files\<unique>\` (existing links are reused). winex11 uses it for XDND drops (`text/uri-list`, file lists) and pasted file lists. |
